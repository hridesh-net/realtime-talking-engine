# Open Knowledge Format (OKF) v0.2

An open specification from Google Cloud (announced June 2026) that formalizes the
"LLM wiki" pattern: package knowledge as a directory of markdown files with YAML
frontmatter, cross-linked into a graph that agents can read. Not tied to any
cloud, database, or model provider; no proprietary account or SDK to read or
write one.

The point of the format is that **producer and consumer are decoupled** — a
bundle hand-authored by a human, generated by an export pipeline, or synthesized
by one model can all be consumed by any of the others.

## Bundle layout

A hierarchical directory of `.md` files. Reserved filenames:

* `index.md` — optional directory listing for progressive disclosure. **No frontmatter**, except `okf_version` in the bundle-root one. Body is sections of `* [Title](link) - description`.
* `log.md` — optional chronological history, newest first, ISO `## YYYY-MM-DD` headings with `* **Update**:` / `* **Creation**:` entries.
* Everything else is a concept document.

## Frontmatter

**Required:** `type` — a short string naming the concept kind. Not centrally
registered; consumers must accept unknown values.

**Recommended:** `title`, `description`, `resource` (a URI for the underlying
asset; absent for abstract concepts), `tags`.

**Trust and provenance:** `sources` (each with `resource`, optionally `id`,
`title`, `author`, `usage_count`, `last_modified`), `usage_window`, `generated`
(`by` required, `at`), `verified` (a list of `{by, at}`; a bare mapping counts as
a one-element list).

**Lifecycle:** `status` (`draft` | `stable` | `deprecated`), `stale_after`.

**Actors** use one of three forms: `<producer>/<version>`, `human:<id>`,
`process:<id>`. Trust tiers derive from this — no `verified` is *unverified*,
machine-only is *machine-confirmed*, a `human:` verifier makes it
*human-reviewed*.

## Linking

Standard markdown. Bundle-relative links starting with `/` are recommended for
stability; relative paths work too. All links are untyped — context supplies the
meaning. Consumers must tolerate broken links.

## Conformance

1. Every non-reserved `.md` file has parseable YAML frontmatter.
2. Every frontmatter block has a non-empty `type`.
3. Reserved filenames follow their structures when present.

Consumers must accept unknown types and unknown keys, tolerate missing
`index.md`, and attempt best-effort consumption of unknown versions rather than
refusing them.

## This bundle

Declares `okf_version: "0.2"` in the root `index.md`, uses `Project`,
`Principle`, `Architecture`, `Map`, `Convention`, `Glossary`, `Subsystem`,
`Contract`, `Module`, `Runbook`, and `Reference` types, and links
bundle-relative throughout. Maintenance process:
[Keeping this bundle current](/concepts/runbooks/okf-maintenance.md).
