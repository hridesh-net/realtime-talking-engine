# Glossary

**Interview** — a job spec plus config, created before anyone is assigned to it.
Not a session. `mode` is `live_interview` or `training_interviewer`.

**Expectation** — the deterministic document telling an interviewer what to
cover, for how long, and how to run the session. One per interview, generated by
the [expectation agent](/concepts/subsystems/expectation-agent.md), stored
one-to-one.

**Archetype** — one of seven fixed persona families in
`candidate_agent/archetypes.py` (catalog `v2.0`). Each exists to stress a
*different manager competency*, and carries fixed trait bounds, knowledge band,
speech spec, answer policy, scorecard, `session_beats` and `stresses`.

**Session beat** — one thing an archetype tends to do during a session
("volunteers a protected personal detail unprompted"). Fed to the *casting*
prompt, where it becomes `always_does` and so reaches the compiled persona
prompt. Model-mediated: a beat is a tendency, not a scripted event.

**Stress profile** — an archetype's `stresses` map: rubric criterion id → 1-4.
Which manager competencies this persona pressures, and how hard. Advisory —
it feeds the picker, and scores nothing.

**Rubric criterion** — one of the five fixed manager competencies: `clarity`,
`structure`, `bias`, `experience`, `communication`. Declared in
`candidate_agent.RUBRIC_CRITERIA` today; `evaluation_agent/rubric.py` will own
them. **No criterion is a critical-fail gate** — the report is an analytical
estimate, and nothing caps or overrides a score.

**Verdict** — `select` | `reject` | `borderline`. Persona metadata since catalog
v2.0: it keeps a cast persona internally consistent and picks the two default
enrollments, but **nothing scores it** — the manager is the assessed subject.
Historically, the answer the interviewer is
supposed to reach about this persona. Fixed by the archetype; the model may not
argue with it.

**Virtual candidate / persona** — one cast of an archetype against a specific
job spec. Stored as a full JSON document, unique on `(interview_id, archetype)`.

**Knowledge band / ceiling** — the archetype's inclusive `(min, max)` competence
range for the job's required skills. Per-skill levels are clamped into it, and
the resulting `knowledge_ceiling` is a **hard runtime limit** the engine must
enforce: a persona that answers above its ceiling invalidates the training
session.

**Breaking point** — the named question depth at which a persona stops being
able to answer on a given skill.

**Stance** — how a persona holds a skill: `solid` | `shallow` | `bluffs` |
`absent`.

**Unlock condition** (`reveals_depth_when`) — what the interviewer must do
before the persona gives a deeper answer. The entire point of `evasive` and
`nervous_fresher`.

**Scorecard** — the ground-truth answer key for grading **the interviewer**, not
the candidate: weighted `must_discover` signals (always summing to 1.0),
`interviewer_failure_modes`, and a `pass_condition`. Never shown to the model
playing the persona.

**Engine contract** — the compiled runtime slice the Go engine consumes:
`system_prompt` (injected verbatim), `opening_line`, `voice_directives`,
`turn_policy`, `knowledge_ceiling`, `unlock_condition`, `forbidden_behaviors`.
Versioned separately from the persona document.

**Session** — one live interview: a human manager talking to one cast persona,
from the persona's opening line to `POST /sessions/{id}/end`. Distinct from an
**Interview**, which is the job spec — many sessions can run against one
interview. Carries a `modality` (`text` today, `voice` when the Go engine
lands).

**Turn** — one line of a session transcript: `index`, `speaker`, `text`, and a
**server-stamped** `at` / `elapsed_ms`. Turn 0 is always the persona's opening
line.

**Manager** — the human being trained, and the speaker label in every
transcript. BRD v3 makes the manager the assessed subject; the older code and
docs still call this person the *interviewer*, and the two mean the same thing.
See [Session transcript](/concepts/contracts/session-transcript.md).

**Modality** — `text` or `voice`, fixed per session. Text turns are generated by
this service; voice turns are spoken between the browser and the realtime vendor
and reported back. Same transcript shape either way.

**Realtime broker** — the port that mints a short-lived credential so a *browser*
can hold a speech-to-speech session with a vendor directly. Not a way to call a
model: no token from it ever reaches this process. See
[Realtime voice](/concepts/contracts/realtime-voice.md).

**Speaker-only** — the current voice mode: one realtime model both decides what
the persona knows and says it, with the knowledge ceiling carried as prompt text
alone. The Go engine's **Thinker** is what turns that into an enforced ceiling;
until it lands, a voice persona is easier to argue past than a text one.

**seed_fingerprint** — SHA256 over the seeded identity only. Stable across
re-casts: "is this the same person?"

**fingerprint** — SHA256 over the whole persona including model-authored text.
Moves on every re-cast: "did this persona change underneath my training set?"

**Default slot** — marks the two archetypes enrolled when the caller does not
choose: `cooperative_trap` (select) and `evasive` (reject). Chosen for rubric
weight, not for hiring outcome — they carry bias and structure between them.

**Adjacent strength** — permission for a persona to be genuinely strong *outside*
the required stack. Set only on `comp_first`, who is genuinely competent and
shops offers on that basis.

**Interviewer challenge** — one sentence naming the manager competency an
archetype exists to stress.

**Port** — a `typing.Protocol` defining storage or model access, depended on by
handlers and agents instead of a concrete adapter.
